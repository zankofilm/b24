# راهنمای ارتقای رابط کاربری اپلیکیشن بازرس — نسخه ۴.۱۲.۱

## مبنای طراحی
این نسخه، رابط Native را مطابق پیش‌نمایش تأییدشده Native 4.2 بازسازی می‌کند؛ نه صرفاً تغییر رنگ قالب ۴.۱۲.۰.

- سربرگ سفید سازمانی با نشان سپر طلایی در سمت راست و برچسب «بازرس» در سمت چپ؛ برچسب نقش، منوی دسترسی‌های تکمیلی را باز می‌کند.
- داشبورد روشن با عنوان «میز کار بازرس» و کارت خوشامدگویی سرمه‌ای ساده؛ تصویر ساختمان از کارت داشبورد حذف شده است.
- وضعیت اتصال و آخرین همگام‌سازی در دو کپسول مستقل.
- چهار کارت آمار در چیدمان ۲×۲ با آیکون‌های ظریف و رنگ‌های ملایم.
- مأموریت‌های اخیر در کارت‌های سفید مستقل با وضعیت، تاریخ و امکان ورود مستقیم به مأموریت.
- نوار ناوبری سفید با چهار مقصد اصلی: خانه، مأموریت‌ها، پیش‌نویس‌ها و حساب.
- صفحه ورود با همان سربرگ، معرفی کوتاه میز کار، فیلدهای ورود و کارت امنیت حساب.

## نصب در GitHub
1. از مخزن فعلی یک branch یا backup بگیرید.
2. محتویات ZIP را در ریشه مخزن GitHub قرار دهید؛ `settings.gradle.kts` و پوشه `app/` باید در ریشه باشند.
3. در Settings → Secrets and variables → Actions → Variables، متغیر `BAZR_API_BASE_URL` را با آدرس کامل HTTPS API که به `/` ختم می‌شود تنظیم کنید.
4. از Actions، workflow ساخت APK را اجرا کنید.
5. پس از موفقیت workflow، فایل Artifact با نام `bazr-inspector-debug` را دریافت کنید.

## دسترسی به بخش‌های تکمیلی
برای اینکه ناوبری پایین دقیقاً مطابق مرجع چهارگزینه‌ای بماند، «ادارات مجاز»، «گزارش رسمی» و «کارتابل سربازرس» از منوی برچسب «بازرس» در سربرگ در دسترس هستند. این صفحات و مجوزهایشان حذف نشده‌اند.

## قابلیت‌های حفظ‌شده
منطق API و احراز هویت دستگاه، اثر انگشت، ادارات مجاز، مأموریت‌ها، چک‌لیست ۸۶ بندی، ذخیره امن پیش‌نویس، دوربین و انتخاب فایل، رمزنگاری مستندات، امضای لمسی، صف ارسال و تلاش مجدد، گزارش رسمی PDF، سوابق و کارتابل سربازرس دست‌نخورده باقی مانده‌اند.

## تنظیم API
در `app/build.gradle.kts` مقدار نمونه `https://example.invalid/api/` فقط fallback ساخت است. مقدار واقعی را در GitHub Actions Variable با نام `BAZR_API_BASE_URL` وارد کنید؛ URL باید HTTPS باشد و با `/` پایان یابد.
