# راهنمای ارتقا به BAZR Android 4.13.1

## قبل از نصب

1. اگر پیش‌نویس یا گزارش ارسال‌نشده روی گوشی دارید، آن‌ها را حذف نکنید.
2. اگر نسخه فعلی برنامه روی گوشی نصب است، امضای APK جدید باید با امضای APK فعلی یکسان باشد.
3. `applicationId` ثابت مانده و `versionCode` از 21 به 23 افزایش یافته است.

## تغییرات مهم

- ورود بیومتریک در صورت نامعتبر شدن کلید پس از تغییر اثر انگشت، به‌صورت کنترل‌شده به ورود با نام کاربری و رمز عبور برمی‌گردد.
- شناسه درخواست فعال‌سازی پس از تأیید دستگاه پاک می‌شود؛ خروج از حساب نیز شناسه و توکن دستگاه را به‌صورت پایدار پاک می‌کند.
- پیش‌نویس، صف ارسال، امضا، متادیتای مستند و رسیدها با نوشتن پایدار ذخیره می‌شوند.
- در صورت خرابی رمزنگاری پیش‌نویس، صف، مستند یا رسید، برنامه داده را خالی فرض نمی‌کند و هشدار یکپارچگی نشان می‌دهد.
- ارقام فارسی و عربی و اعشار محلی پشتیبانی می‌شوند؛ جداکننده‌های تکراری و گروه‌بندی نامعتبر رد می‌شوند.
- عکس‌های دوربین تا ۲۴ مگابایت در حافظه خصوصی رمزنگاری می‌شوند؛ PDF حداکثر ۱۲ مگابایت است.
- نوار وضعیت و نوار ناوبری برای Android 15 و SDK 35 با inset واقعی مدیریت می‌شوند.

## ساخت با GitHub

1. فایل ZIP کامل را در ریشه مخزن جایگزین کنید.
2. در GitHub → Settings → Secrets and variables → Actions → Variables، متغیر `BAZR_API_BASE_URL` را تنظیم کنید.
3. در تب Actions، Workflow را اجرا کنید.
4. نتیجه تست‌های واحد و فایل APK را از Artifact دریافت کنید.

## امضای APK و حفظ اطلاعات گوشی

**مهم:** ساخت Debug روی Runner موقت GitHub از کلید Debug همان Runner استفاده می‌کند؛ این کلید در اجرای بعدی ثابت نیست. بنابراین APK Debug جدید ممکن است روی نسخه Debug قبلی نصب نشود و Android خطای امضای متفاوت بدهد.

برای به‌روزرسانی بدون حذف برنامه، Keystore همان نسخه نصب‌شده را در GitHub Secrets قرار دهید:

- `BAZR_KEYSTORE_BASE64`
- `BAZR_KEYSTORE_PASSWORD`
- `BAZR_KEY_ALIAS`
- `BAZR_KEY_PASSWORD`

اگر Keystore نسخه نصب‌شده را ندارید، قبل از حذف برنامه از اطلاعات محلی و وضعیت گزارش‌های ارسال‌نشده نسخه پشتیبان مطمئن تهیه کنید. ساخت یک Keystore جدید، امضای APK قبلی را بازتولید نمی‌کند.

## آزمون بعد از نصب

1. ورود با نام کاربری و رمز عبور.
2. بررسی تأیید دستگاه و همگام‌سازی مأموریت‌ها.
3. فعال‌سازی اثر انگشت، خروج از برنامه و ورود مجدد با اثر انگشت.
4. آزمایش ورود با رمز عبور پس از غیرفعال‌سازی/تغییر اثر انگشت در تنظیمات گوشی.
5. باز کردن مأموریت و وارد کردن امتیاز با ارقام فارسی مثل `۹۵` و عربی مثل `٩٥`.
6. ثبت توضیح برای امتیاز کمتر از ۶۰ و پیوست یک عکس و یک PDF.
7. بستن برنامه و باز کردن دوباره آن؛ بررسی حفظ پیش‌نویس.
8. مرور گزارش، امضای لمسی، قرار گرفتن در صف و ارسال.
9. قطع اینترنت حین ارسال و سپس تلاش مجدد؛ بررسی حفظ امضا و مستندات.
10. کنترل رسید در بخش گزارش‌های رسمی.

ساخت موفق APK به‌تنهایی به معنی تأیید اتصال API، ثبت گزارش روی هاست یا سلامت همه سناریوهای گوشی نیست.
