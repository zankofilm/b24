# سامانه بازرسی ادارات — Android Native 4.13.1

این مخزن سورس اپلیکیشن بومی اندروید بازرس است. رابط کاربری با Kotlin و Viewهای Native ساخته شده و از WebView استفاده نمی‌کند.

## تغییرات نسخه 4.13.1

- اصلاح ورود بیومتریک و پاک‌سازی کلید Keystore نامعتبر پس از تغییر اثر انگشت.
- حذف شناسه فعال‌سازی پس از تأیید دستگاه و خروج امن از حساب.
- ذخیره پایدار امضا، صف ارسال، متادیتای مستندات و رسیدها.
- جلوگیری از نمایش پیش‌نویس رمزنگاری‌شده خراب به‌عنوان پیش‌نویس خالی و جلوگیری از بازنویسی آن.
- بازیابی فهرست صف ارسال و تاریخچه از نام رکوردهای رمزنگاری‌شده پس از قطع ناگهانی فرایند.
- پشتیبانی از ارقام فارسی و عربی در امتیازدهی و تبدیل جداکننده اعشار محلی.
- اعتبارسنجی شناسه سؤال، شناسه مأموریت و امضای محتوای فایل‌های پیوست.
- پشتیبانی از عکس‌های دوربین تا ۲۴ مگابایت در گاوصندوق محلی؛ فایل PDF همچنان حداکثر ۱۲ مگابایت است.
- افزایش مهلت انتقال فایل و قطع قطعی اتصال HTTP در تمام مسیرهای ارسال.
- مدیریت خطای callbackهای UI برای جلوگیری از کرش در پاسخ ناقص سرور.
- اعمال صحیح insets نوار وضعیت و ناوبری در Android 15 و هدف SDK 35.
- ذخیره پایدار پیش‌نویس‌ها و جلوگیری از اعلام موفقیت قبل از ثبت واقعی اطلاعات.
- بازیابی دقیق‌تر رکوردهای ناقص صف و رسید و نمایش هشدار به‌جای ناپدید شدن داده خراب.
- رد ورودی‌های امتیاز با جداکننده‌های تکراری یا گروه‌بندی نامعتبر.
- افزودن تست‌های واحد برای امتیازدهی، ارقام فارسی/عربی، جداکننده‌ها و سیاست فشرده‌سازی تصویر.
- افزودن پشتیبانی اختیاری از امضای ثابت Release با Keystore متعلق به سازمان.

## تنظیم آدرس API

در GitHub از مسیر **Settings → Secrets and variables → Actions → Variables** یک Repository Variable با نام زیر بسازید:

`BAZR_API_BASE_URL`

مقدار باید آدرس کامل HTTPS پوشه API و دارای `/` در انتها باشد؛ برای نمونه:

`https://your-domain.example/api/`

آدرس نمونه بالا فقط قالب است؛ آدرس واقعی هاست خودتان را قرار دهید.

## ساخت APK با GitHub Actions

1. سورس را در ریشه مخزن GitHub قرار دهید؛ پوشه `app/` و فایل `settings.gradle.kts` باید در ریشه پروژه باشند.
2. مقدار `BAZR_API_BASE_URL` را در Variables تنظیم کنید.
3. از تب **Actions**، Workflow با نام **Build BAZR Inspector Android (debug)** را اجرا کنید.
4. Workflow ابتدا تست‌های واحد را اجرا می‌کند و سپس APK را می‌سازد.
5. در صورت نبود Keystore سازمانی، خروجی Debug فقط برای تست است و کلید امضای آن روی هر Runner جدید متفاوت خواهد بود.

## امضای پایدار برای به‌روزرسانی بدون حذف برنامه

برای انتشار قابل نصب روی نسخه قبلی، باید APK جدید با **همان Keystore نسخه نصب‌شده** امضا شود. چهار GitHub Repository Secret زیر را تنظیم کنید:

- `BAZR_KEYSTORE_BASE64`: محتوای فایل JKS/keystore به‌صورت Base64
- `BAZR_KEYSTORE_PASSWORD`: رمز Keystore
- `BAZR_KEY_ALIAS`: نام Alias
- `BAZR_KEY_PASSWORD`: رمز کلید Alias

پس از تنظیم این Secrets، Workflow به‌جای Debug یک APK از نوع Release با امضای ثابت می‌سازد. اگر APK فعلی با کلید دیگری امضا شده باشد، تغییر کلید بدون حذف نسخه نصب‌شده ممکن نیست؛ ابتدا باید برنامه و داده‌های محلی آن را با روش امن پشتیبان‌گیری/انتقال مدیریت کرد.

## ساخت محلی

با JDK 17، Android SDK Platform 35 و Gradle 8.13:

```bash
gradle :app:testDebugUnitTest -PBAZR_API_BASE_URL="https://your-domain.example/api/"
gradle :app:assembleDebug -PBAZR_API_BASE_URL="https://your-domain.example/api/"
```

## نکات فنی و محدودیت‌های آزمون

- `applicationId` برای حفظ امکان ارتقا همان `ir.bazr.inspection` باقی مانده است.
- `versionCode` برابر 23 و `versionName` برابر `4.13.1` است.
- `minSdk` برابر 30 و `targetSdk` برابر 35 است.
- اطلاعات حساس در SharedPreferences رمزنگاری‌شده با AES-GCM و کلید Android Keystore نگهداری می‌شوند.
- فایل‌های مستند در گاوصندوق خصوصی برنامه با AES-GCM رمزنگاری می‌شوند؛ نسخه اصلی فایل تا دریافت رسید سرور حفظ می‌شود.
- تست‌های منطق خالص Kotlin در محیط توسعه اجرا شده‌اند؛ ساخت کامل Android APK و تست روی دستگاه واقعی باید توسط GitHub Actions و سپس گوشی انجام شود.
- سازگاری کامل API فقط با سورس/نسخه واقعی PHP هاست قابل تأیید است؛ این بسته شامل سورس بک‌اند PHP نیست.
