# راهنمای ارتقای سامانه بازرسی به نسخه ۴.۱۸.۰

## ترتیب نصب
برای فعال‌شدن کامل صندوق ابلاغیه، ابتدا پچ سرور را نصب کنید و سپس APK جدید را بسازید.

### ۱. پشتیبان‌گیری
- از Repository گیت‌هاب و نسخه سالم APK ۴.۱۷ نسخه پشتیبان بگیرید.
- از فایل‌های `pro.js` و فایل‌های API موجود روی هاست کپی پشتیبان بگیرید.
- اطلاعات برنامه و حافظه گوشی را پاک نکنید؛ Clear Data نزنید.

### ۲. نصب پچ سرور
ZIP پچ سرور را در پوشه اصلی سامانه استخراج کنید؛ ساختار مقصد باید این‌گونه باشد:
- فایل‌های `api/*.php` در همان پوشه `api` فعلی قرار بگیرند.
- `pro.js` در همان مسیر فعلی `pro.js` جایگزین شود.
- فایل‌های جدید `mobile_notice_common.php`, `mobile_notice_admin.php`, `mobile_notice_poll.php`, `mobile_notices.php`, `mobile_notice_read.php` به پوشه `api` اضافه شوند.
- `api/mobile_sync.php` و `pro.js` جایگزین نسخه‌های قبلی شوند.

**SQL جدید لازم نیست.** ماژول از `entity_records`, `mobile_devices`, `mobile_users` و `mobile_nonces` موجود استفاده می‌کند.

### ۳. ساخت APK
1. ZIP سورس کامل اندروید را در ریشه Repository جایگزین کنید.
2. متغیر Repository به نام `BAZR_API_BASE_URL` باید آدرس کامل HTTPS پوشه API و دارای `/` انتهایی باشد.
3. در GitHub → Actions، Workflow ساخت Android را اجرا کنید.
4. ابتدا Unit Test و کنترل منابع و سپس APK ساخته می‌شود.
5. نام Artifact: `bazr-inspector-4.18.0-apk`.

### ۴. آزمون پنل وب
1. با حساب دارای مجوز مدیریت گزارش‌ها وارد پنل شوید.
2. به بخش «ابلاغ و مکاتبات» بروید.
3. گزینه «ایجاد ابلاغ برای اپ بازرس» را بزنید.
4. یک بازرس مشخص را انتخاب کنید؛ ابتدا از ارسال همگانی برای تست استفاده نکنید.
5. عنوان، متن، اولویت و در صورت نیاز نوع/شناسه مرجع را وارد و ارسال کنید.
6. نتیجه باید با پیام ثبت موفق در پنل نمایش داده شود.

### ۵. آزمون اپ بازرس
1. APK ۴.۱۸ را روی نسخه قبلی نصب کنید؛ اگر خطای امضا مشاهده شد، نسخه قبلی را حذف نکنید.
2. وارد حساب بازرس شوید و همگام‌سازی انجام دهید.
3. تب «ابلاغیه‌ها» را باز کنید؛ ابلاغیه اختصاصی باید نمایش داده شود.
4. پیام را باز کنید؛ وضعیت خواندن باید ثبت شود.
5. پنل وب را دوباره بارگذاری کنید؛ رسید مشاهده باید در کارت ابلاغیه قابل مشاهده باشد.
6. در تنظیمات اعلان، مجوز اعلان اندروید را فعال کنید.
7. با اینترنت روشن، برنامه را ببندید و پس از اجرای دوره‌ای WorkManager، اعلان جدید را بررسی کنید.

## زمان‌بندی اعلان پس‌زمینه
WorkManager حداقل بازه ۱۵ دقیقه‌ای دارد و اندروید ممکن است اجرا را به‌دلیل Doze، محدودیت باتری یا سیاست سازنده گوشی عقب بیندازد. این Push آنی نیست. برای اعلان فوری واقعی، Firebase Cloud Messaging و تنظیمات سرویس سمت سرور لازم است.

## حفظ داده
- پیش‌نویس‌ها، امضاها، مستندات و نواقص محلی حذف نمی‌شوند.
- خروج از حساب، اعتبار اعلان پس‌زمینه را پاک و زمان‌بندی را لغو می‌کند.
- رسید خواندن آفلاین در حافظه رمزنگاری‌شده نگهداری و در همگام‌سازی بعدی ارسال می‌شود.
